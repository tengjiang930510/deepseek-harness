# 企业插件实现与边界

本文面向维护武汉地铁企业集成的开发者，描述当前仓库中的插件、独立服务及其接口、状态和已知限制。准确的配置字段以各插件的 `cordis.patch.yml`、源码和包内 README 为准；开发和发布规则见 [开发规范](./DEVELOPING.md)。

## 组成和调用关系

| 组件 | 类型 | 主要职责 | 不负责 |
|---|---|---|---|
| [t4y-tenant](#t4y-tenant) | Host / Client 插件 | 保存当前系统租户和项目上下文 | 认证、授权判定 |
| [t4y-identity](#t4y-identity) | Host / Client 插件 | 企业登录、会话恢复、模型凭据桥接 | 插件目录的权限判定 |
| [t4y-brand](#t4y-brand) | Client 插件 | 展示企业和项目品牌 | 登录、加载业务插件 |
| [t4y-capability-hub](#t4y-capability-hub) | Client 插件 | 授权插件页面、快捷按钮和命令候选 | 最终授权、插件安装 |
| [t4y-release-manager](#t4y-release-manager) | Host 插件 | 查询授权、读取发布信息和管理插件 | 代替企业系统授予权限 |
| [t4y-trial-runtime](#t4y-trial-runtime) | Host / 配置插件 | 模型和联网搜索运行时配置 | 企业登录、签发模型 Key |
| [oa-helper](#oa-helper) | Host / Client 插件 | 办公申请命令、模型工具和确认卡片 | 企业权限管理、出差的远程提交 |
| [t4y-key-broker](#t4y-key-broker) | 独立服务，不是 DSH 插件 | 为企业用户管理模型凭据 | 管理 DSH 插件或企业菜单 |

典型链路：企业用户登录 → identity 获取身份与项目、向 Broker 申请模型 Key → tenant 同步当前上下文 → capability-hub 请求 release-manager 查询菜单及表单 → 用户安装或启用授权插件 → 会话通过命令或工具调用业务插件。品牌仅消费身份及项目展示数据。

`tenantId` 是登录返回的系统租户，`moduleId` 是当前企业项目，表单中的 `项目名` 是 Hub 插件坐标；三者不可互换。切换项目保留当前工作区与历史对话，不提供项目间历史会话隔离。

## t4y-tenant

**职责和入口。** [`index.js`](./t4y-tenant/index.js) 提供 Host 服务 `ctx.t4yTenant`，维护系统租户、当前项目、Hub 目录地址及变化监听；[`client.js`](./t4y-tenant/client.js) 提供浏览器侧上下文。identity 在登录、恢复、切换项目或退出时更新上下文，release-manager 使用当前项目查询企业系统。

**状态和边界。** Host 当前上下文位于进程内，浏览器视图由 identity 会话及事件驱动。上下文的存在不代表账号已获授权；插件安装和启用仍需企业系统查询。该服务不校验密码、不签发 Key、不隔离会话，也不应把 Hub 的项目名当作 `moduleId`。

**验证重点。** 登录、恢复、切项目和退出后，Host 与浏览器的项目一致；项目切换期间到达的旧授权响应不能改变新项目状态。参见 [包说明](./t4y-tenant/README.md) 和 [开发说明](./t4y-tenant/DEVELOPING.md)。

## t4y-identity

**职责和入口。** [`client.js`](./t4y-identity/client.js) 管理企业登录门禁、项目选择、恢复、退出和用户界面；[`index.js`](./t4y-identity/index.js) 对接 tenant、Broker、凭据存储与模型配置。企业登录流程取得公钥并加密密码，调用企业登录、用户信息和项目菜单接口；Host 使用企业访问令牌向 Broker 请求模型 Key，写入 `T4Y_NEW_API_KEY` 凭据槽，并从模型服务读取模型列表。

**状态和边界。** 企业 access token 和项目等会话资料保存在浏览器本地存储；模型 Key 由 Host 凭据槽保存，浏览器会话不保存模型 Key 明文。浏览器偏好可保留账号及上次项目。模型 Key 按用户及首次签发项目管理；项目切换不重签 Key。登录态或 Key 失效会触发门禁；页面恢复及 Key 签发失败不能当作成功登录。具体网络响应和服务器端策略以实际接口为准。

**副作用与依赖。** 登录可能写凭据槽及模型设置，退出请求撤销 Key 并清理本地状态；这些动作与 release-manager 的菜单授权是不同判断。当前 Desktop 小窗口切换依赖原生 `dshOnboarding.setCompact` 桥，不能声称由独立插件完全实现。完整接口与过期规则见 [包说明](./t4y-identity/README.md)。

**验证重点。** 正常登录、无项目、签发失败、过期、退出、恢复，以及多项目切换；检查会话不被误清除，不能跨账号复用授权或模型凭据。业务环境中不得在日志和测试输出中打印密码、令牌或 Key。

## t4y-brand

**职责和入口。** [`client.js`](./t4y-brand/client.js) 读取 identity 的企业与项目资料，渲染侧栏及会话首屏品牌。项目名称和 logo 优先，企业品牌作为后备；远程图片不可用时使用内置图。源码和资源生成关系见 [开发说明](./t4y-brand/DEVELOPING.md)。

**边界。** 品牌只影响显示，不证明企业身份或插件授权。远程图片由浏览器加载，其缓存行为取决于浏览器和服务端响应；不能承诺完全不发生网络请求。切换和恢复时应更新显示，并测试图片失败后的回退与闪烁。

## t4y-capability-hub

**职责和入口。** [`client.js`](./t4y-capability-hub/client.js) 注册“授权插件”设置页、会话输入区快捷入口和 `/` 命令候选。它向 release-manager 请求当前用户、项目可见的插件坐标与安装状态；根据表单 `插件种类` 分组，未填写时使用企业菜单上级目录，`插件图标` 使用上传图片地址并提供失败回退。

**调用逻辑。** 设置页发起安装、启用与停用；快捷按钮只在相应插件已安装、启用且用户选择展示时显示。点击快捷按钮和选择斜杠候选均插入命令，用户确认后发送；命令解析及执行由 DSH 命令机制负责。快捷选择按企业、账号及项目保存，旧请求由身份及代次检查拦截。

**缓存和权限。** 插件名称、图标地址、版本、命令等展示资料可放浏览器本地存储；每次新页面、重新登录、切换项目或相关状态变化仍需重新确认授权。同一页面内会复用授权快照；企业系统只有查询接口时，后台收权不会自动实时推送到已经打开的页面，刷新或重新登录后重新查询。不能把本地缓存当作授权凭据，也不能将未授权坐标仅因缓存存在而展示。

**边界和验证。** 本插件负责用户界面，不直接决定权限；最终安装和启用由 Host 再次核验。命令候选适配依赖 DSH 输入控制器和菜单槽位，升级 DSH 要复验 `/`、`@`、鼠标、键盘、窄窗口、logo、重复命令、加载失败和项目切换。细节见 [包说明](./t4y-capability-hub/README.md)。

## t4y-release-manager

**职责和入口。** [`index.js`](./t4y-release-manager/index.js) 提供 `ctx.t4yReleaseManager` 和 `/api/t4y-release` 接口。它使用企业 access token 与当前 `moduleId` 查询用户可见菜单，遍历表单叶子并读取 `插件名`、`项目名`、`插件种类` 和 `插件图标`；缺少必需坐标的记录不构成插件。同一坐标重复时报错，部分明确不可用的表单按实现跳过，其他查询错误向调用方返回。

**发布与安装。** 对授权坐标读取 Hub 上的 `latest.json`，校验仓库、提交、源码路径等发布信息，再委托 DSH `pluginManager` 安装；安装和授权启停时重新查询企业授权。发布状态保存在 profile 的 `.dsh-plugin-releases.json`，使用不可变提交定位版本；项目切换只停用当前未授权的受管理包，不卸载。因切项目自动停用的包再次获得授权时可恢复；用户手动停用不应被当作自动停用恢复。

**列表及生命周期。** 活动期间过滤普通插件列表中的平台包和受本服务管理的包；授权插件通过专用页面管理，普通第三方包仍可显示。平台包的受保护操作被拒绝；卸载服务时恢复其接管的插件管理方法。企业服务失败、项目变化或发布信息不合法时不得将旧展示缓存当作新授权。具体状态和接口见 [包说明](./t4y-release-manager/README.md)。

**验证重点。** 表单字段映射、目录回退、重复坐标、非法图标、查询失败、授权收回、项目往返、手动停用保持、并发旧响应、最新版本安装及插件卸载恢复。当前过滤使用对 `pluginManager` 方法的适配，DSH 升级时须验证方法兼容和生命周期。

## t4y-trial-runtime

**职责和入口。** [`cordis.patch.yml`](./t4y-trial-runtime/cordis.patch.yml) 组合试用模型、Agent 和工具配置；[`index.js`](./t4y-trial-runtime/index.js) 注册联网搜索提供方并处理相关配置；[`runtime.js`](./t4y-trial-runtime/runtime.js) 保存运行时辅助逻辑。模型和搜索使用 identity 管理的 `T4Y_NEW_API_KEY` 凭据引用。

**边界。** 本插件不登录、不签发 Key，也不决定企业菜单授权。搜索依赖模型代理及网络；配置或上游失败时不得把空结果视为已成功检索。插件启动会对 profile patch 执行特定迁移，维护者应先核对 [`migrateProfilePatch`](./t4y-trial-runtime/index.js) 的作用范围，并验证用户配置不被无关删除。模型、搜索和凭据生命周期以 [包说明](./t4y-trial-runtime/README.md) 及 identity 为准。

## oa-helper

**职责和入口。** [`index.js`](./oa-helper/index.js) 注册 `/oa-helper`、`office_workflow_prepare` 和 `zjy_leave_submit`；[`client.js`](./oa-helper/client.js) 展示和保存申请卡片。用户输入描述后，命令把内容交给 Agent 分析，工具提取明确的信息并生成可编辑卡片；卡片用于用户核对，正常准备阶段不提交远程流程。

**数据与副作用。** 请假、出差及办公事项分别呈现字段；卡片编辑和已提交状态使用浏览器本地存储。请假卡片的确认按钮调用 `/oa-helper submit`，属于可能产生真实办公流程的操作；出差及其他办公事务目前仅本地确认。禁止将测试中的真实提交当成无副作用操作。

**当前限制。** 提交实现动态加载 `lib/leave-open.js`，当前仓库缺少该文件，因此请假远程提交通道会返回模块不可用错误，不能声称已完成真实提交。浏览器本地卡片状态不是远端审批系统的事实来源。模型可能无法可靠提取未提供的信息，未知字段应由用户确认；卡片应作为本轮最后显示的内容，发布前要用真实模型和界面复验。参见 [包说明](./oa-helper/README.md)。

## t4y-key-broker

**职责和入口。** [`server.py`](./t4y-key-broker/server.py) 是独立 Key Broker，`server.mjs` 是旧原型；它调用企业用户信息接口验证身份，与 New API 管理接口协作签发、查询和撤销模型 Key。`/v1/session/issue`、`/status`、`/revoke` 面向 identity，管理接口另需管理凭据。

**状态和边界。** SQLite 账本保存用户、归属项目、有效期和 Key 材料；Key 按用户管理，首次签发时的项目是用量归属。切换项目不会自动改账单归属；退出撤销后重新登录才可能重建归属。单机 SQLite 不等于多机共享状态；企业身份缓存、网络故障、上游管理接口和实际部署安全均影响结果。Broker 不作为 DSH bundle 安装，不管理企业菜单授权。配置、管理员接口及运维限制见 [服务说明](./t4y-key-broker/README.md)。

## 桌面载体与非插件代码

企业插件位于 `tsy-custom-plugins/`，但当前桌面实现仍包含原生改动：Electron 主进程的登录窗口尺寸及 IPC、插件种子复制、桌面打包脚本，以及子进程 Node 路径传递。插件在 Desktop Host 启动后才运行，不能在没有宿主扩展点的情况下自行替代启动前的窗口和安装包逻辑。迁移这些部分前必须先实现并验证等价的部署或宿主扩展方案，不得直接删除。

桌面试用包默认载入平台插件；`oa-helper` 通过授权流程安装，不属于默认种子。未签名测试包不等于已签名、公证的正式发布包。
