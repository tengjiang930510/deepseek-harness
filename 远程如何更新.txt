下次官方有更新，在 F:\projects\deepseek-harness 里做（不要再用 D 盘那份 zip）。


cd F:\projects\deepseek-harness
# 1. 把官方最新历史拉到本机（不改你正在编辑的文件）
git fetch upstream
# 2. 把官方 master 叠到你当前分支上，百炼那次 commit 会跟在后面
git rebase upstream/master
# 3. 若有冲突：打开 git 标出的文件，改完后
#    git add <那些文件>
#    git rebase --continue
#    想放弃这次 rebase：git rebase --abort
# 4. 依赖和生成物
pnpm install
# 5. 推到你的 fork（rebase 改写了历史，需要 --force-with-lease，不要用 --force）
git push --force-with-lease origin master
冲突多半只在接线处：packages/bundle/base/cordis.patch.yml、package.json、apps/desktop/src/main.ts、project-manager.ts。packages/web/web-search-bailian/ 一般不用动。

--force-with-lease 的原因：rebase 之后本地 master 的“形状”变了，普通 git push 会被拒。它只会在 GitHub 上的 master 仍是你上次推送的那个提交时才覆盖；别人如果又推了新提交，它会失败而不是盲盖。

网页上的 Sync fork 也可以用，但有自定义 commit 时容易多出一个 merge。更稳的是上面这套 fetch + rebase。

合完如果改到了 Session 事件或文档地图，再跑：


pnpm run gen-tsconfig-paths
pnpm run gen-doc-graphs
pnpm run gen-config-catalog
pnpm run gen-plugin-packages
新事件类型才需要重新 persistence-changes --record。只是官方改了别处、百炼事件没动，就不用 record。
